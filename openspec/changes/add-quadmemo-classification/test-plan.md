# Test Plan

文字数上限導入後の前提: スクロール・50件復元の入力は1文字チップ50件（連結99文字）とする。51件目を切り捨てた通知は「一部のみ登録しました。」を含む。

specs/word-classification/spec.md（14 シナリオ）と specs/memo-persistence/spec.md（10 シナリオ）の
全 24 シナリオを、E2E で検証可能な観点へ翻訳したもの。受け入れ基準の原本は spec のシナリオであり、
本ファイルで新しい仕様は定義しない。

前提:

- 表示ラベルは `update-quadmemo-fixed-labels` の固定値に従う。旧ラベルの保存値自体は移行しない。

- 分類・正規化の網羅的な組合せは Vitest（`src/core/`）で検証し、E2E は「辞書に従って象限が変わる」ことを利用者視点で確認する代表ケースに絞る（仕様書 §7.4 がユニットテストを必須としている）
- 設定値の編集 UI は本 change には無いため、部分一致・重複抑止の観点は fixture が端末内保存へ直接設定値を書いた状態から始める（design.md - D9）
- 完全一致モードでは最長一致規則が結果を分けないため、最長一致の観点は部分一致 fixture で検証する（design.md - D2）
- 実行プロジェクトは `chromium` と `mobile-safari` の 2 面

### 異常系・境界の検討結果

- **異常系**: 保存失敗（TP-021）と保存不可環境（TP-022）を E2E に含めた。保存失敗のうち削除操作の失敗経路はリポジトリ層のユニットテストへ委譲（下表）
- **多重送信**: 同一語の連続コミットは重複許可設定の観点（TP-012・TP-013）で覆う。1 コミット 50 件の一括書き込みは TP-024 でトランザクション境界を確認する
- **空データ**: 保存データが無い初回起動を TP-018 で確認する。正規化後に空となる入力は Vitest へ委譲（下表）
- **権限境界**: 本アプリは認証・権限の概念を持たないため該当なし

## E2E対象外(委譲先と理由)

| シナリオ | 委譲先 | 理由 |
|---------|--------|------|
| 正規化後に空になるトークンの破棄 / 正規化後に空になる入力はチップにならない | Vitest（`src/core/normalize.ts` / `classify.ts`） | 結合文字のみ・不可視文字のみといった入力を UI 経由で安定に投入しづらい。純粋関数の入出力で網羅する方が確実 |
| ストレージ永続化の要求 / 起動時に永続化を要求し結果を保持する | Vitest（`navigator.storage.persist` をモックした起動処理のテスト）＋ 実機手動確認 | 権限付与の結果はブラウザとインストール状態に依存し、E2E で意味のある結果を作れない。設定画面での表示は `add-quadmemo-dictionaries` の観点になる |
| 正規化・マッチングの網羅（半角カタカナ、全角英数、長音符、複数マッチの組合せ、部分一致の双方向、空文字・記号） | Vitest（`src/core/__tests__/`） | 仕様書 §7.4 でユニットテスト必須と定義されている領域。E2E では代表ケース（TP-001〜TP-011）のみ確認する |
| 保存失敗時の扱い / 移動・編集・削除が保存に失敗する経路 | Vitest（`src/db/repository.ts` とストアアクションのテスト） | 失敗注入の組合せが多く、E2E で全経路を回すと実行時間に見合わない。追加経路（TP-021）で仕組みの妥当性を確認し、残りは単体で網羅する |
| 端末内での保存と復元 / 長期未使用によるストレージ削除からの復旧 | 実機手動確認＋`add-quadmemo-dictionaries` のエクスポート/インポート観点 | OS のストレージ回収を再現できない。バックアップ手段の提供が対処であり、本 change の範囲外 |
