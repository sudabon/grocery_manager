# Test Plan

specs/pwa-shell/spec.md の全 14 シナリオを、E2E で検証可能な観点へ翻訳したもの。
受け入れ基準の原本は spec のシナリオであり、本ファイルで新しい仕様は定義しない。

前提:

- PWA 系の観点はビルド成果物を配信する preview サーバーに対して実行する（`pwa` プロジェクト）。開発サーバーでは Service Worker の事前キャッシュが本番と一致しないため検証にならない（design.md - D6）
- `pwa` は iPhone 13 プリセットに `browserName: 'chromium'` を上書きして実行する。Safari 固有の Service Worker・オフライン動作は既存の iPhone 実機受け入れへ委譲する（design.md - D6）。既存 UI の `mobile-safari` 回帰検証は WebKit のまま維持する
- Service Worker の登録完了は、アプリがオフライン利用可能になったことを表す状態で待つ（`waitForTimeout` は使わない）
- 更新の適用（`skipWaiting` → リロードによる差し替え）は 2 世代のビルド配信が必要で E2E ではフレークの温床になるため、通知の表示までを E2E の対象とし、実適用は実機検証へ委譲する（design.md - D7）
- ホーム画面追加そのもの（iOS の共有シート操作）は自動化できないため実機検証へ委譲する

### 異常系・境界の検討結果

- **異常系**: オフライン（TP-003〜TP-006）と未キャッシュ状態でのオフライン初回訪問（TP-013）を含めた。Service Worker 登録失敗（非対応環境）は下表で委譲
- **多重送信**: 更新通知からの更新操作の連打は、実適用が E2E 対象外のため委譲する（実機検証で 1 回のみ適用されることを確認）
- **空データ**: 保存データが無い状態でのオフライン起動は TP-003 のバリエーションとして扱い、独立観点にはしない（初期データ投入は `add-quadmemo-classification` の観点で担保済み）
- **権限境界**: 該当なし

## E2E対象外(委譲先と理由)

| シナリオ | 委譲先 | 理由 |
|---------|--------|------|
| インストール可能なアプリとしての配信 / ホーム画面から起動すると全画面で表示される | 実機手動検証（仕様書 §15 の受け入れ基準） | ホーム画面への追加は iOS の共有シート操作であり自動化できない。standalone 表示の見え方も実機でしか確認できない |
| 更新の検知と適用 / 通知から更新すると新バージョンに切り替わる | 実機手動検証（2 世代を `deploy.sh` で配信して確認） | `skipWaiting` → リロードによる差し替えの検証には 2 世代のビルド配信と Service Worker のライフサイクル待ちが必要で、E2E ではフレークになる（design.md - D7） |
| 更新の検知と適用 / 更新操作の多重実行 | 実機手動検証 | 実適用が E2E 対象外であるため、同じ経路で確認する |
| オフラインでの起動と動作 / Service Worker 非対応環境での挙動 | 実機・ブラウザ手動確認 | 対象プラットフォーム（iOS Safari）は Service Worker に対応しており、非対応環境は想定外。アプリは SW 無しでも動作する（オフライン起動のみができない）ことを手動で確認する |
| `index.html` / `sw.js` / `manifest.webmanifest` / `icons/icon-192.png` / `icons/icon-512.png` / `icons/apple-touch-icon-180.png` の計 6 パスが `no-cache` で配信されること | デプロイ後の実測（`curl -I`）＋ `static-hosting` の要求 | 配信ヘッダーはインフラ側の要求であり、実アセットが出る本 change のタイミングで実測する（design.md - D8）。E2E の baseURL がローカル preview のときは配信ヘッダーが本番と異なるため意味を持たない |
| アイコンの見た目（マスカブルのセーフゾーン、ホーム画面での表示） | 実機手動確認 | 画像の意匠は自動判定できない |
