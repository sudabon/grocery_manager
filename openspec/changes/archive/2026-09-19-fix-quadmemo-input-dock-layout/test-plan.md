# Test Plan

specs/ 配下の全シナリオ（memo-board「モバイル入力時の操作性」の追加 4 件）を、E2E で検証可能な観点へ翻訳したもの。
受け入れ基準の原本は spec のシナリオであり、本ファイルで新しい仕様は定義しない。

前提:

- ソフトウェアキーボードは E2E から出せない。キーボードに隠れた量（`--keyboard-inset`）の算出は `useVisualViewport` の単体テストで固定し、E2E ではその量を直接与えて配置（ドックが持ち上がりボードが縮む）だけを検証する（design.md - D3）
- 辞書は空（`seed:empty-board`）。すべてのチップは Q4 に未分類で置かれる
- chromium と mobile-safari の両方で実行する。ビューポート依存（iPhone 13 相当の高さ）の観点は mobile-safari が本命
- 既存の `expectIndependentScroll`（add-quadmemo-quadrant-ui TP-002）は末尾チップが一部でも見えれば通るため、末尾チップの全体が象限内にあることを別観点で検証する

### 異常系・境界の検討結果

- **異常系**: キーボード分のパディングで他の要素が収まらない場合（design.md - D4）は、ビューポートの高さの検証になるため E2E の対象外。TP-004 の量は iPhone 13 相当で収まる 200px にする
- **境界値**: 視覚ビューポートがレイアウトと同じ（差 0）・視覚ビューポートがレイアウトより下にある（差が負 → 0 に丸める）は単体テストで固定する
- **多重送信**: 該当なし
- **空データ**: チップ 0 件の状態は TP-001 / TP-002 / TP-004 が兼ねる
- **権限境界**: 該当なし

## E2E対象外(委譲先と理由)

| シナリオ | 委譲先 | 理由 |
|---------|--------|------|
| キーボードに隠れた量の算出（縮小・スクロール・復帰・購読解除・入力バーを閉じている間は公開しない・`visualViewport` 未対応） | Vitest（`useVisualViewport` / `InputBar` の単体テスト） | Playwright はソフトウェアキーボードを出せず `visualViewport` も動かせない。stub で固定する |
| 閉じている入力バーがフローから外れる（`collapsed`） | Vitest（`InputBar` の単体テスト）+ TP-001 | クラスの付け外しは単体で、結果の高さは TP-001 で検証する |
| 実機のキーボード表示中の配置とセーフエリア分の余白 | 実機手動検証（design.md - D3） | OS のキーボードと `env(safe-area-inset-bottom)` は E2E から再現できない |
