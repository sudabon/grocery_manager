# Test Plan

specs/ 配下の全シナリオ（daily-boards 10 件・memo-persistence 6 件・memo-board 8 件・data-portability 7 件・board-image-share 8 件）を、E2E で検証可能な観点へ翻訳したもの。
受け入れ基準の原本は spec のシナリオであり、本ファイルで新しい仕様は定義しない。

前提:

- 日付の基準は JST 固定（design.md - D1）。テストは日付が変わる瞬間に不安定になるため、**時刻を固定できる仕組みが必須**。fixture 側で `Date.now` を固定する（`env:fixed-clock`）
- 「日付が変わったあとに開く」観点は、固定時刻を 2 つの日付にまたいで切り替えることで作る（`env:clock-advanced`）
- 複数日付にチップがある状態を作るシードが必要（`seed:boards-across-days`）
- 旧版（日付なし・`schemaVersion` 1）のインポート検証には固定ファイルが必要（`files/legacy-v1.json`）
- 画像内の日付文字列は PNG のピクセルから読めないため、画像の内容は `board-image-share` design - D5 と同じくユニットへ委譲する

### 異常系・境界の検討結果

- **異常系**: 版数拒否（TP-017）、過去ボードでの操作不可（TP-007 / TP-008）を含めた
- **境界値**: JST 0:00 直前・直後の日付判定はユニットへ委譲する（下表）。日付越えの挙動そのものは TP-001 / TP-003 で見る
- **多重送信**: 過去ボードでの書き込み拒否は UI で手段が無く（TP-007 / TP-008）、store 側の最後の砦（design.md - D4）はユニットへ委譲する
- **空データ**: 当日 0 件（TP-006 / TP-022）と、過去のボードが無い状態（TP-006）を確認する
- **権限境界**: 該当なし。読み取り専用は日付による区分であり権限ではない

## E2E対象外(委譲先と理由)

| シナリオ | 委譲先 | 理由 |
|---------|--------|------|
| 日付ごとのボード / JST 日付の算出（0:00 直前・直後、UTC との境界） | Vitest（`boardDate.ts` の単体テスト） | 固定オフセットの計算であり純粋関数で網羅するのが適切。E2E で境界時刻を並べても観測できる事実は増えない |
| 過去ボードは読み取り専用 / store 側での書き込み拒否 | Vitest（`useAppStore` の単体テスト） | UI で手段を提供しないこと（TP-007 / TP-008）が利用者から見える振る舞い。store の拒否は多重の防御で、内部状態の検証になる |
| 過去ボードは読み取り専用 / 書き込みの瞬間に日付が変わっていた場合の拒否 | Vitest（`useAppStore` の単体テスト） | design.md - D4 の副作用。E2E で日付越えとコミットのタイミングを合わせるのは不安定 |
| 既存メモの日付への移行 / IndexedDB の version 2 への移行処理 | Vitest（`repository` の単体テスト） | `upgrade` の中の処理であり、E2E は移行後の表示（TP-014）で確認する |
| ボード画像の内容 / 画像にそのボードの日付が含まれる、他の日付のチップは含まれない | Vitest（描画入力の純粋関数） | PNG のピクセルから日本語と日付を読むのは E2E に向かない（`board-image-share` design - D5）。E2E はファイル名の日付（TP-020 / TP-021）までを見る |
| ボード画像の内容 / チップがあるボードの画像にラベルと本文が含まれる | Vitest（描画入力の純粋関数） | 同上。既存 `board-image-share` の判断を踏襲する |
| 全データのエクスポートとインポート / 識別子が衝突するメモは追加されない、上書き確認を中止すると何も変わらない | 既存 `add-quadmemo-dictionaries` の観点 | 本 change で振る舞いが変わらない |

## タグ対応

- すべての実装テストに `@add-quadmemo-daily-boards` と `@TP-NNN` を付与すること
- 新規 fixture `env:fixed-clock` / `env:clock-advanced` / `seed:boards-across-days` / `seed:legacy-memos-without-date` / `files/legacy-v1.json` を `tests/e2e/fixtures/README.md` に登録すること
- 既存 fixture `env:web-share-stub` / `env:no-web-share` / `files/unsupported.json` は登録済みのものを再利用する
- **`env:fixed-clock` はほぼ全観点の前提になる。** 日付が変わる瞬間に既存の全 change の E2E が不安定になるため、時刻固定の仕組みは本 change の実装の最初に用意すること
