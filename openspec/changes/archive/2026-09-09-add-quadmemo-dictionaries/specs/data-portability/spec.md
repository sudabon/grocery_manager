## Purpose

端末内にのみ存在するメモ・辞書・設定を JSON として持ち出し、別の状態から復元できるようにするための振る舞いを定義する。iOS ではストレージが失われる可能性があるため、エクスポートはバックアップ手段として位置づける。

## ADDED Requirements

### Requirement: 辞書のエクスポートとインポート

辞書編集画面は、4 象限の辞書を 1 つの JSON として出力できなければならない（MUST）。出力には版数（`version`）と、象限ごとのラベル・単語リストを含めなければならない（MUST）。

辞書のインポートは、入力内容を検証してから適用しなければならない（MUST）。検証に失敗した場合はエラーを表示し、既存データを一切変更してはならない（MUST NOT）。

#### Scenario: 辞書をエクスポートすると復元可能な JSON が得られる

- **WHEN** 辞書編集画面からエクスポートを実行する
- **THEN** 版数と 4 象限すべてのラベル・単語リストを含む JSON が受け取れる

#### Scenario: 不正な内容のインポートは何も変更しない

- **WHEN** JSON として壊れている、または必要な項目を欠く内容をインポートする
- **THEN** エラーが表示され、辞書の内容は変更前のままである

#### Scenario: 正しい辞書 JSON のインポートで辞書が置き換わる

- **WHEN** 正しい形式の辞書 JSON をインポートする
- **THEN** 4 象限のラベルと単語リストがインポート内容に置き換わり、以後のコミットの分類に反映される

### Requirement: 全データのエクスポートとインポート

設定画面は、メモ・辞書・設定を含む全データを 1 つの JSON として出力できなければならない（MUST）。出力には `schemaVersion` と出力時刻を含めなければならない（MUST）。

全データのインポートは `schemaVersion` を検証しなければならない（MUST）。対応しない版数の場合はエラーを表示し、既存データを変更してはならない（MUST NOT）。メモは既存の識別子と衝突しないものだけを追加しなければならない（MUST）。辞書と設定は上書きとなるため、適用前に利用者の確認を得なければならない（MUST）。確認を中止した場合、何も変更してはならない（MUST NOT）。

#### Scenario: 全データをエクスポートして復元できる

- **WHEN** 全データをエクスポートし、メモを全削除したあとにそのファイルをインポートする
- **THEN** メモ・辞書・設定がエクスポート時点の状態に復元される

#### Scenario: 対応しない版数のインポートは拒否される

- **WHEN** 対応しない `schemaVersion` を持つファイルをインポートする
- **THEN** エラーが表示され、既存のメモ・辞書・設定は変更されない

#### Scenario: 識別子が衝突するメモは追加されない

- **WHEN** 既存メモと同じ識別子を含むファイルをインポートする
- **THEN** 衝突したメモは追加されず、同じ内容のチップが二重に並ばない

#### Scenario: 上書き確認を中止すると何も変わらない

- **WHEN** 全データのインポートで辞書・設定の上書き確認を中止する
- **THEN** メモ・辞書・設定はいずれも変更されない

### Requirement: エクスポートの受け渡し手段

システムは、エクスポートしたファイルを端末の共有機能で受け渡せなければならない（MUST）。共有機能が利用できない環境では、ファイルのダウンロードで受け取れなければならない（MUST）。

#### Scenario: 共有機能が使えない環境ではダウンロードで受け取れる

- **WHEN** 共有機能が利用できない環境でエクスポートを実行する
- **THEN** ファイルがダウンロードとして受け取れる

#### Scenario: 共有機能が使える環境では共有が呼び出される

- **WHEN** 共有機能が利用できる環境でエクスポートを実行する
- **THEN** エクスポートしたファイルを含む共有が呼び出される
