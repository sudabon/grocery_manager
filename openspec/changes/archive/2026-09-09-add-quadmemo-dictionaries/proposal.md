## Why

`add-quadmemo-classification` までで、辞書に従った自動分類と端末内保存は動く。しかし辞書とラベルは初期シードのまま、設定値は既定のまま変更できない。QuadMemo は「自分の用途に合わせた 4 象限」を作ってこそ意味があるため、辞書と設定を利用者が編集できる状態にする。

同時に、データ持ち出し手段（エクスポート/インポート）を用意する。iOS ではインストール済み Web アプリでも長期未使用時にストレージが削除されるリスクがゼロではなく（仕様書 §8.4）、端末内保存のみの構成ではバックアップ手段が唯一の保険になる。エクスポートは「便利機能」ではなくデータ保全の要件として扱う。

## What Changes

- 辞書編集画面（`/dictionaries`）を実装する: Q1〜Q4 の切替、象限ラベルの編集、単語リストの編集（1 行 1 語のテキスト編集）、明示的な保存
- 保存時の整形を実装する: 空行除去 → 前後空白トリム → 正規化後の重複除去 → 保存 → 正規化済みキャッシュの再構築（仕様書 §5.2）
- 辞書編集画面に運用ヘルプ（複合語は分割後の単位で登録する）を表示する（仕様書 §7.1）
- 設定画面（`/settings`）を実装する: `partialMatch`、`autoCommitMs`（500〜5000ms のスライダー）、`allowDuplicates`、`showDictationHint`
- 設定画面にメモ全削除（2 段階の確認）を実装する
- 設定画面にアプリ情報を表示する: アプリバージョン、ストレージ永続化の結果、外部送信を行わないというプライバシー方針、定期バックアップの推奨
- 辞書のみの JSON エクスポート / インポート（バリデーション付き）を実装する（仕様書 §5.2）
- 全データ（メモ＋辞書＋設定）の JSON エクスポート / インポートを実装する。`schemaVersion` を検証し、メモは既存 ID と衝突しないものだけ追加、辞書・設定は上書き確認を経る（仕様書 §8.3）
- エクスポートの受け渡しは Web Share API を第一手段とし、非対応時はファイルダウンロードへフォールバックする

本 change の範囲外（後続 change）:

- manifest / Service Worker / オフライン起動 / 更新通知、および設定画面での Service Worker 更新状態の表示（`add-quadmemo-pwa-offline`）

## Capabilities

### New Capabilities

- `dictionary-management`: 4 象限の辞書（ラベルと単語リスト）を編集・保存する振る舞い。保存時の整形、既存チップを再分類しないこと、運用ヘルプの提示を含む
- `app-settings`: 分類とコミットの挙動を変える設定値の編集、メモ全削除、アプリ情報とプライバシー方針の提示
- `data-portability`: 辞書および全データの JSON エクスポート / インポートによるデータ持ち出しと復元

### Modified Capabilities

（なし。`word-classification` は「設定が有効な場合」の振る舞いを既に定義しており、本 change はその設定を変更する手段を追加する）

## Impact

- **新規**: `src/pages/DictionariesPage.tsx` の実装、`src/pages/SettingsPage.tsx` の実装、`src/core/portability.ts`（エクスポート整形・インポート検証）、`src/components/ConfirmDialog.tsx`
- **変更**: `src/db/repository.ts`（全データの一括読み出し・一括書き込み）、`src/store/useAppStore.ts`（辞書保存・設定更新・全削除・インポート適用）、`src/pages/MemoPage.tsx`（ヒント表示が設定に追従）
- **依存追加**: なし（バリデーションは手書きの型ガードで実装し、ライブラリ依存を増やさない）
- **データ**: エクスポート形式は `schemaVersion: 1`（仕様書 §8.3）。以後スキーマを変える場合はこの版数で判定する
- **リスク領域**: インポートは既存データを上書きし得る操作であり、確認と検証の設計が中心的な関心事になる
