## Why

入力されたテキストは `Intl.Segmenter` の分かち書きでトークンへ割られる。この分割は一般語彙の単位なので、利用者にとって 1 語である商品名が複数に割れる。実測で「鶏むね肉」は `鶏 / むね / 肉`、「キッチンペーパー」は `キッチン / ペーパー`、「オリーブオイル」は `オリーブ / オイル` になる。

辞書照合（`word-classification`）は分割後のトークン単位で行うため、割れた語を辞書へ登録しても到達できない。利用者から見ると「辞書に『鶏むね肉』を登録したのに、コミットすると 3 枚のチップになり、どれも Q4 に落ちる」という状態になり、買い出しメモとして意味のある単位でチップを作れない。

辞書へ登録した語は、その利用者にとって 1 語である。分割の段階で辞書を参照すれば、既存の辞書がそのまま「語彙の定義」としても働き、新しい辞書も新しい設定も UI も増やさずに解決できる。

## What Changes

- 単語分割の後段に、**辞書エントリと完全一致する連続トークン列を 1 つのトークンへ結合する**処理を追加する
- 結合には既存の 4 象限の辞書エントリをそのまま使う（新しい辞書・新しい設定は増やさない）
- 結合は先頭から順に、より長い一致を優先する
- 結合の判定は完全一致のみとし、設定「部分一致を許可」は使わない（部分一致は従来どおり、結合後のトークンの分類にだけ効く）
- 句読点・記号・空白などの区切りを跨いで結合しない
- チップには結合前の原文をそのまま連結した表記を表示する（正規化後の表記にはしない）
- 1 コミット 50 件の上限、象限ごとの 100 文字上限、重複抑止は、いずれも結合後のトークンに対して適用する

破壊的変更ではない。辞書に「分かち書きで割れる語」が登録されていない限り、分割結果は現在と同じになる。既定の初期辞書（`にんじん` / `たまねぎ` / `キャベツ` / `じゃがいも` / `牛乳` / `卵` / `鶏肉` / `チーズ`）はいずれも単一トークンで割れないため、初期状態の振る舞いは変わらない。

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

- `word-classification`: 辞書エントリによるトークンの結合規則を追加する。正規化・最長一致という既存の照合規則を、分割の段階にも適用する
- `memo-board`: 「コミットテキストのチップ化」に、辞書に登録された語は分割しないことを加える
- `dictionary-management`: 登録単位のヘルプを、分割後の単位ではなく、1 つのチップにしたい語全体を登録する案内へ更新する

## Impact

- `src/core/tokenize.ts`: 単語セグメントと区切りの境界を保ったまま結合できるようにし、辞書を受け取れるようにする
- `src/core/classify.ts`: `NormalizedDicts` に、結合の探索を打ち切るための最長エントリ長を持たせる
- `src/core/commitText.ts`: 分割時に `normalizedDicts` を渡す。50 件の切り詰めは結合後のトークンに対して行う
- テスト: `src/core/__tests__/tokenize.test.ts` / `commitText.test.ts` の拡充、E2E `tests/e2e/update-quadmemo-dictionary-tokenization.spec.ts` と fixture の追加
- データ: IndexedDB のスキーマ・エクスポート形式は変更しない
- 既存データ: 遡及しない。すでに割れて保存されているチップは割れたまま残る
- 性能: 結合は辞書の完全一致 Map への参照だけで行い、エントリ数に比例した走査を増やさない

## 記録した前提

- 結合に使う辞書は既存の 4 象限辞書とした。「複合語専用の辞書」を別に設ける案は、同じ語を二重に登録させることになり、利用者から見た「辞書に登録する」という操作が 2 種類に増えるため採らない
- 空白・句読点を跨ぐ結合（`オリーブ オイル` を `オリーブオイル` として扱う）は行わない。原文に区切りがある以上、利用者は別の語として入力したと解釈する。区切りなしで登録した語は区切りなしの入力に一致する
- 部分一致で結合しない。`鶏むね` を `鶏むね肉` へ寄せるような結合は、原文に無い語をチップにすることになる。結合の根拠は「原文の並びが辞書の語と同じであること」に限る
