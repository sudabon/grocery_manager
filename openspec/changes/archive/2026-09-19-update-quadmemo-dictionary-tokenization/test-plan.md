# Test Plan

specs/ 配下の全シナリオ（word-classification 6 件・memo-board 4 件・dictionary-management 1 件）を、E2E で検証可能な観点へ翻訳したもの。
受け入れ基準の原本は spec のシナリオであり、本ファイルで新しい仕様は定義しない。

前提:

- 結合に使う辞書は既存の 4 象限辞書。判定は完全一致のみで、区切り（空白・句読点）を跨がない（design.md - D3 / D4）
- 実測した分かち書きの結果を前提にする: `鶏むね肉` → `鶏 / むね / 肉`、`鶏ムネ肉` → `鶏 / ム / ネ / 肉`、`むね肉` → `むね / 肉`、`キッチンペーパー` → `キッチン / ペーパー`、`オリーブオイル` → `オリーブ / オイル`、`ミニトマト` → `ミニ / トマト`
- 割れる語を登録した新規シードが必要（`seed:dict-compound` / `seed:dict-compound-partial`）
- 象限ラベルは固定（Q1 それ以外 / Q2 野菜 / Q3 肉類・乳製品 / Q4 ドラッグストア）

### 異常系・境界の検討結果

- **異常系**: 区切りを跨ぐ入力（TP-004）と、部分一致では結合しないこと（TP-005）を含めた
- **境界値**: 結合するトークン数の上限（`maxEntryLength` による打ち切り）、エントリが空の辞書、1 文字エントリはユニットへ委譲する（下表）。E2E で並べても観測できる事実が増えない
- **多重送信**: 同じ語を続けてコミットしたときの重複抑止は既存 `add-quadmemo-classification` の観点で担保済み。結合後の正規化文字列で判定されることはユニットで固定する
- **空データ**: 辞書が空の状態で従来どおり分割されることは、既存 `seed:empty-board` を使う `add-quadmemo-quadrant-ui` の観点が担保する
- **権限境界**: 該当なし

## E2E対象外(委譲先と理由)

| シナリオ | 委譲先 | 理由 |
|---------|--------|------|
| 複合語の登録に関する運用ヘルプ / 登録単位のヘルプが表示される | 既存 `add-quadmemo-dictionaries` の登録ヘルプ E2E | 既存観点の期待する案内を、語全体の登録と区切りの制約へ更新する |
| コミットテキストのチップ化 / 複数単語のコミットで単語ごとのチップができる | 既存 `add-quadmemo-quadrant-ui` の観点 | 本 change で振る舞いが変わらない。辞書に登録の無い語の分割結果は従来と同一 |
| コミットテキストのチップ化 / 単語分割 API が使えない環境でもチップが生成される | 既存 `add-quadmemo-quadrant-ui` の観点（`env:no-intl-segmenter`）＋ Vitest（`tokenize` の単体テスト） | フォールバック経路も結合処理を通すが、分割が粗いため結合は発生しない。経路を通ること自体は単体で固定し、E2E の観点は既存のまま維持する |
| 結合の探索打ち切り（正規化後の最長エントリ長を超えたら伸ばさない）と計算量 | Vitest（`tokenize` の単体テスト） | 内部の探索規則であり、利用者から見える結果は TP-001〜TP-006 と同一 |
| 50 件上限が結合後のトークンに適用されること | Vitest（`commitText` の単体テスト） | 結合は件数を減らす方向にしか働かず、利用者に見える通知は既存の部分登録と同じ。既存 `add-quadmemo-memo-length-limit` の部分登録通知の観点が通知そのものを担保する |
| 重複抑止が結合後の正規化文字列で判定されること | Vitest（`commitText` / ストアの単体テスト） | 重複抑止の見え方は既存 `add-quadmemo-classification` の観点で担保済み。判定に使う文字列が結合後であることは内部規則 |
| 象限ごとの 100 文字上限との関係 | Vitest（`quadrantLength` / `commitText` の既存テスト） | 結合はチップ数を減らし連結長を縮める方向で、新たに拒否される入力が生じない。既存テストの回帰確認で足りる |
