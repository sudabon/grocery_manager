## Why

QuadMemo のメモは端末内の IndexedDB にだけあり、別の人へ「今のボードを見せる」手段が JSON バックアップしかない。JSON は復元用であり、アプリを持たない相手が店先で一覧を見る用途に向かない。共有シート経由で 4 象限の画像を渡せれば、サーバや共同編集を足さずに参照専用の受け渡しができる。

## What Changes

- メモ画面に「画像で共有」ボタンを追加する
- 現在の 4 象限（象限ラベルとチップ本文）を PNG 画像として組み立て、端末の共有機能へ渡す
- 共有機能が使えない環境では、同じ PNG をダウンロードとして受け取れるようにする
- 画像の受け渡しは端末の共有シートに任せ、特定アプリ（LINE 等）へ直接送信しない
- 共有はスナップショットであり、メモ・辞書・設定は変更しない
- 既存の JSON エクスポート / インポート（バックアップ）は変更しない

本 change の範囲外:

- LINE SDK / LIFF / Messaging API など特定アプリへの直接送信
- 共有リンク・サーバ保存・認証
- 相手側での編集権限や同期
- 画面のスクリーンショット撮影（入力バーやヘッダーを写し込む方式）

## Capabilities

### New Capabilities

- `board-image-share`: メモ画面から 4 象限ボードの画像を組み立て、端末の共有機能（非対応時はダウンロード）で受け渡す振る舞い。共有は読み取り専用のスナップショットであり、端末内データは変更しない

### Modified Capabilities

（なし。`data-portability` は JSON によるバックアップと復元を定義しており、本 change は復元不能な参照用画像を別経路で渡す。`memo-board` の配置・入力・チップ操作の要求は変更しない）

## Impact

- **新規**: ボード画像の組み立て（キャンバス描画）と、メモ画面の共有導線
- **変更**: `src/pages/MemoPage.tsx`（共有ボタン）、既存のファイル共有ヘルパを画像ファイルにも使える形へ一般化、E2E の共有スタブ（PNG では本文ではなく MIME 種別を記録する）
- **依存追加**: なし（ブラウザの Canvas と既存の Web Share API を使う）
- **データ**: IndexedDB のスキーマは変更しない。画像は端末内でその場で生成し、永続化しない
- **プライバシー**: アプリから外部へ自動送信しない。渡す先は利用者が共有シートで選ぶ
