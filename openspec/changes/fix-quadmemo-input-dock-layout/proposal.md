## Why

iPhone（ホーム画面に追加した PWA）のメモ画面で、下部のマイク周りの帯がマイクボタン（64px）に対して約 168px + セーフエリアと大きく、ボードの表示領域を常に削っている。さらに象限を末尾までスクロールしても最下部のチップが見えない。入力バーを閉じた状態ではボードの下端がマイク周りの帯に隠れ、キーボード表示中は持ち上がった入力ドックの裏に隠れる。

原因は、ボードの表示領域が入力ドックの「実際の描画位置・高さ」ではなく固定値に依存していることにある。入力ドックは `position: fixed` で画面に貼り付き、メモ画面側が固定の下パディング（168px + セーフエリア）で場所を空けている。閉じている入力バーも `visibility: hidden` のままフロー内に残って高さを占め、キーボード表示中はドックを `transform` で持ち上げるだけでボード側は縮まない。実機では固定値の想定と実際の描画位置がずれ、閉じた状態でもボードの下端が帯に隠れる。

音声メモの主画面であり、書いたメモの末尾が読めないのは日常の利用に直接響くため直す。

## What Changes

- 入力ドックを `position: fixed` からメモ画面のフロー内（最後の要素）へ移し、ボードは構造的にドックの直上で終わるようにする。固定の下パディングは廃止する
- 入力バーを閉じている間はフローから外して高さを持たせず、ドックの高さをマイクボタンと最小限の余白に収める（常時マウントと同期 `focus()` は維持する）
- ソフトウェアキーボード表示中は、キーボードに隠れた量だけメモ画面の下パディングを増やして入力ドックを押し上げ、同時にボードを縮める。ドックを `transform` で持ち上げる方式は廃止する
- キーボードで持ち上がっている間は、セーフエリア分の下余白を付けない

破壊的変更ではない。入力欄の常時マウント・同期 `focus()`・コミット制御は変えない。

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

- `memo-board`: 「モバイル入力時の操作性」に、入力ドックがボードと重ならないこと、閉じている間のドックの高さ、キーボード表示中にボードが縮んで象限内スクロールで末尾チップまで見えることを要件として追加する

## Impact

- `src/styles.css`: `.memo-page` の下パディング、`.input-dock` の配置、`.input-bar.collapsed` の追加
- `src/components/InputBar.tsx`: 閉じている間の `collapsed` クラス、`useVisualViewport(open)` の呼び出し
- `src/hooks/useVisualViewport.ts`: ドックの `transform` ではなく `--keyboard-inset` を公開する形へ変更
- テスト: `src/hooks/__tests__/useVisualViewport.test.tsx` の書き直し、`src/components/__tests__/InputBar.test.tsx` の追加、E2E `tests/e2e/fix-quadmemo-input-dock-layout.spec.ts` の追加
- データ・設定・スキーマは変更しない

## 記録した前提

- Chrome / Playwright WebKit の iPhone 相当ビューポートでは、閉じた状態でボードとドックの間に 20px の余裕があり、実機（PWA）の「閉じた状態でも隠れる」は再現しない。固定値と `position: fixed` に依存する構造自体を無くすことで、実機の位置基準がどうずれていても重ならないようにする
- ソフトウェアキーボードは Playwright から出せない。キーボードに隠れた量の算出は単体テストで、その量を与えたときの配置は E2E で検証し、実機のキーボード表示は手動検証に委ねる
