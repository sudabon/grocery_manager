## Purpose

画面を座標平面のように 4 分割したメモボード上で、入力されたテキストを単語ごとのチップとして象限へ配置し、チップを操作できるようにするための、メモ画面の外部観測可能な振る舞いを定義する。

## ADDED Requirements

### Requirement: 4 象限ボードの表示

メモ画面は、画面を 2×2 に等分割した 4 つの象限（右上 Q1、左上 Q2、左下 Q3、右下 Q4）を表示しなければならない（MUST）。各象限には象限ラベルを表示しなければならない（MUST）。象限内のチップは追加順に折り返して並べ、表示領域を超えた場合は当該象限内でスクロールできなければならない（MUST）。象限内のスクロールは画面全体のスクロールへ連鎖してはならない（MUST NOT）。

#### Scenario: 初期表示で 4 象限とラベルが見える

- **WHEN** 利用者がメモ画面を開く
- **THEN** 4 つの象限が等分割で表示され、各象限のラベルが読み取れる

#### Scenario: チップがあふれた象限だけがスクロールする

- **WHEN** ある象限のチップが表示領域を超える件数になる
- **THEN** その象限内を縦スクロールして全チップを確認でき、他の象限とボード全体の位置は変わらない

### Requirement: マイクボタンと入力バーの状態遷移

メモ画面の下部にはマイクボタンを常時表示しなければならない（MUST）。マイクボタンは 2 つの状態を持つ:

- **idle**: マイクアイコンを表示する。タップすると入力バーを表示し、テキスト入力欄へフォーカスを移す（＝ソフトウェアキーボードが起動する）MUST
- **inputting**: 閉じるアイコンを表示する。タップすると入力バーを閉じる MUST

#### Scenario: マイクボタンのタップで入力バーが開きフォーカスが移る

- **WHEN** idle 状態でマイクボタンをタップする
- **THEN** 入力バー（テキスト入力欄と確定ボタン）が表示され、テキスト入力欄がフォーカスを持つ

#### Scenario: 入力バーを閉じるとマイクボタンが idle に戻る

- **WHEN** inputting 状態で閉じるボタンをタップする
- **THEN** 入力バーが非表示になり、マイクボタンがマイクアイコン（idle）に戻る

### Requirement: コミットのトリガー

入力欄のテキストは、次のいずれかのうち最も早く成立した契機でコミットされなければならない（MUST）:

1. **自動コミット**: 最後の入力から自動コミット待機時間（既定 1500ms）が経過し、かつ日本語入力の変換中でない場合
2. **手動コミット**: 確定ボタンのタップ、または Enter キーの押下
3. **クローズ時コミット**: 入力バーを閉じる操作時に未コミットのテキストが残っている場合

コミット後は入力欄をクリアしなければならない（MUST）。入力バーが開いている限りフォーカスを維持し、続けて入力できなければならない（MUST）。変換中（composition 中）は自動コミットしてはならない（MUST NOT）。

#### Scenario: 無入力の経過で自動コミットされる

- **WHEN** 入力欄にテキストを入力し、自動コミット待機時間を超えて操作しない
- **THEN** テキストがコミットされてチップになり、入力欄が空になる

#### Scenario: 確定ボタンで即時コミットされる

- **WHEN** 入力欄にテキストがある状態で確定ボタンをタップする
- **THEN** 待機時間を待たずにテキストがコミットされ、入力欄が空になる

#### Scenario: Enter キーでコミットされる

- **WHEN** 入力欄にテキストがある状態で Enter キーを押す
- **THEN** テキストがコミットされ、入力欄が空になる

#### Scenario: 変換中は自動コミットされない

- **WHEN** 日本語入力の変換が未確定のまま自動コミット待機時間を超える
- **THEN** コミットは発生せず、入力中のテキストは入力欄に残る

#### Scenario: コミット後もフォーカスが維持され連続入力できる

- **WHEN** コミットが発生した直後に、再タップせずに続けてテキストを入力する
- **THEN** 入力は同じ入力欄で受け付けられ、次のコミットでもチップが追加される

#### Scenario: 入力バーを閉じる操作で未コミットのテキストがコミットされる

- **WHEN** 入力欄にテキストが残った状態で入力バーを閉じる
- **THEN** そのテキストがコミットされてチップになり、その後に入力バーが閉じる

### Requirement: コミットテキストのチップ化

コミットされたテキストは単語単位のトークンへ分割され、トークン 1 つごとにチップ 1 つを生成しなければならない（MUST）。句読点・記号・空白のみのトークン、および前後の空白を除去すると空になるトークンは破棄しなければならない（MUST）。チップにはコミットされた原文のトークンを表示しなければならない（MUST）。

#### Scenario: 複数単語のコミットで単語ごとのチップができる

- **WHEN** 複数の単語を含むテキストをコミットする
- **THEN** 単語ごとに 1 つずつチップが生成され、コミット順に象限へ並ぶ

#### Scenario: 句読点だけのトークンは破棄される

- **WHEN** 単語と句読点を含むテキストをコミットする
- **THEN** 単語のチップのみが生成され、句読点のチップは生成されない

#### Scenario: 単語分割 API が使えない環境でもチップが生成される

- **WHEN** 実行環境が単語分割 API に対応していない
- **THEN** 空白・句読点による分割にフォールバックし、チップの生成は継続される

### Requirement: チップの配置先と未マッチの識別

チップは分類結果の象限へ配置されなければならない（MUST）。分類でマッチしなかったトークン（辞書が未設定の場合を含む）は既定象限である右下（Q4）へ配置しなければならない（MUST）。未マッチで既定象限へ配置されたチップは、自動分類されたチップと視覚的に区別できなければならない（MUST）。

#### Scenario: 辞書が無い状態ではすべて既定象限へ入る

- **WHEN** 辞書が 1 語も設定されていない状態でテキストをコミットする
- **THEN** すべてのチップが右下（Q4）に配置され、未マッチの見た目で表示される

#### Scenario: 未マッチチップが見た目で区別できる

- **WHEN** 未マッチのチップと自動分類されたチップが同時に存在する
- **THEN** 2 種類のチップは異なる見た目で表示され、利用者が区別できる

### Requirement: コミット結果の境界処理

コミット結果のトークンが 0 件の場合、システムは何も表示・通知してはならない（MUST NOT）。1 回のコミットで 50 件を超えるトークンが得られた場合、先頭 50 件のみを処理し、一部のみ登録したことを利用者へ通知しなければならない（MUST）。

#### Scenario: 空のコミットでは何も起きない

- **WHEN** 空文字または記号のみのテキストをコミットする
- **THEN** チップは追加されず、通知も表示されない

#### Scenario: 50 件を超えるトークンは切り捨てて通知する

- **WHEN** 1 回のコミットで 50 件を超えるトークンを含むテキストを投入する
- **THEN** 先頭 50 件のチップのみが追加され、一部のみ登録した旨の通知が表示される

### Requirement: チップの操作

チップをタップするとアクションシートを表示しなければならない（MUST）。アクションシートは「Q1〜Q4 への移動」「編集」「削除」を提供し、現在の象限への移動は選択できない状態にしなければならない（MUST）。移動・編集・削除の結果はボードに即時反映されなければならない（MUST）。編集結果が空（空白のみを含む）になった場合は、そのチップを削除しなければならない（MUST）。手動で移動または編集したチップは、以後の自動分類の対象から外れなければならない（MUST）。

#### Scenario: アクションシートで現在の象限が選べない

- **WHEN** ある象限のチップをタップする
- **THEN** アクションシートが開き、そのチップが今いる象限への移動項目は選択できない

#### Scenario: チップを別の象限へ移動する

- **WHEN** アクションシートから別の象限への移動を選ぶ
- **THEN** チップは移動先の象限へ表示され、元の象限からは消える

#### Scenario: チップのテキストを編集する

- **WHEN** アクションシートから編集を選び、テキストを変更して確定する
- **THEN** チップの表示が変更後のテキストになる

#### Scenario: チップを削除する

- **WHEN** アクションシートから削除を選ぶ
- **THEN** そのチップがボードから消え、他のチップは残る

#### Scenario: 編集で空文字にするとチップが削除される

- **WHEN** アクションシートから編集を選び、テキストを空にして確定する
- **THEN** そのチップはボードから削除される

### Requirement: 画面遷移

メモ画面のヘッダーから辞書編集画面と設定画面へ遷移できなければならない（MUST）。各画面からメモ画面へ戻れなければならない（MUST）。3 つの画面はそれぞれ固有のパス（メモ `/`、辞書編集 `/dictionaries`、設定 `/settings`）を持たなければならない（MUST）。

#### Scenario: 辞書編集画面へ遷移して戻る

- **WHEN** メモ画面のヘッダーから辞書編集の導線を選び、その後で戻る操作をする
- **THEN** 辞書編集画面が表示され、戻る操作でメモ画面に戻る

#### Scenario: 設定画面へ遷移して戻る

- **WHEN** メモ画面のヘッダーから設定の導線を選び、その後で戻る操作をする
- **THEN** 設定画面が表示され、戻る操作でメモ画面に戻る

### Requirement: モバイル入力時の操作性

入力欄はフォーカス時に画面が自動拡大されないフォントサイズ（16px 以上）でなければならない（MUST）。ソフトウェアキーボードが表示されている間、入力バーはキーボードに隠されてはならない（MUST NOT）。画面下部の操作エリアは端末のセーフエリア（ホームバー等）と重なってはならない（MUST NOT）。操作要素のダブルタップによる拡大、およびチップ長押しによるテキスト選択・コールアウト表示は抑止しなければならない（MUST）。

#### Scenario: 入力欄フォーカスで画面が拡大されない

- **WHEN** 入力欄にフォーカスする
- **THEN** 画面の表示倍率は変わらない

#### Scenario: キーボード表示中も入力バーが見える

- **WHEN** ソフトウェアキーボードが表示された状態で入力バーを操作する
- **THEN** 入力バーと確定ボタンはキーボードの上に見えており、タップできる

#### Scenario: セーフエリアと操作エリアが重ならない

- **WHEN** セーフエリアを持つ端末でメモ画面を表示する
- **THEN** マイクボタンはセーフエリアに被らず、全体がタップできる

### Requirement: アクセシビリティと控えめなモーション

マイクボタンとチップには、操作対象が分かるアクセシブルネームを与えなければならない（MUST）。アクションシートを表示している間、フォーカスはアクションシート内に留めなければならない（MUST）。利用者がモーション低減を設定している場合、チップの配置アニメーションを無効化しなければならない（MUST）。

#### Scenario: 支援技術からマイクボタンとチップを識別できる

- **WHEN** 支援技術でメモ画面の操作要素を読み上げる
- **THEN** マイクボタンと各チップはそれぞれの役割・内容が分かる名前で識別できる

#### Scenario: アクションシート表示中はフォーカスが外に出ない

- **WHEN** アクションシートを開いた状態でフォーカス移動操作を繰り返す
- **THEN** フォーカスはアクションシート内の項目を巡回し、背後のボードへは移らない

#### Scenario: モーション低減設定でアニメーションが無効になる

- **WHEN** モーション低減を有効にした環境でコミットする
- **THEN** チップは移動アニメーションなしで対象象限に表示される
