# Test Plan

specs/memo-board/spec.md の全 30 シナリオを、E2E で検証可能な観点へ翻訳したもの。
受け入れ基準の原本は spec のシナリオであり、本ファイルで新しい仕様は定義しない。

前提:

- ディクテーション（キーボードのマイクキー）は OS 機能であり自動化できない。仕様書 §6 のとおり手入力も同じコミットパイプラインを通るため、E2E は入力欄への手入力経路で検証する
- 実行プロジェクトは `chromium`（ロジック系観点の回帰）と `mobile-safari`（レイアウト・タップ・ビューポート依存観点）の 2 面。レイアウト依存の観点は `mobile-safari` を主とする
- ソフトウェアキーボードの出現・セーフエリアは Playwright で再現できないため、該当観点は実機手動検証へ委譲する

## E2E対象外(委譲先と理由)

| シナリオ | 委譲先 | 理由 |
|---------|--------|------|
| コミットのトリガー / 変換中は自動コミットされない | Vitest（`useCommitController` の単体テスト） | 変換中状態は IME に依存し、E2E からは合成 composition イベントに頼るしかなく不安定。コミット制御を hook として切り出し、composition 開始・終了とタイマーの相互作用を単体で検証する（design.md - D4） |
| チップの配置先と未マッチの識別 / 未マッチチップが見た目で区別できる（自動分類チップとの同時比較） | `add-quadmemo-classification` の E2E | 本 change では辞書が存在せず、自動分類されたチップを作れないため 2 種類を同時に並べられない。未マッチ側の表示のみ TP-014 で検証し、比較は分類 change で行う |
| モバイル入力時の操作性 / キーボード表示中も入力バーが見える | 実機手動検証（受け入れ基準） | Playwright はソフトウェアキーボードを表示できず、`VisualViewport` の変化を再現できない。iPhone 実機で確認する |
| モバイル入力時の操作性 / セーフエリアと操作エリアが重ならない | 実機手動検証（受け入れ基準） | `env(safe-area-inset-*)` はデバイスエミュレーションでは値が入らない。iPhone 実機（ホーム画面追加後の standalone）で確認する |
| モバイル入力時の操作性 / 入力欄フォーカスで画面が拡大されない（拡大挙動そのもの） | 実機手動検証（受け入れ基準） | 自動ズームは iOS Safari の挙動であり再現不可。発生条件（フォントサイズ 16px 以上）は TP-024 で担保する |
| コミットテキストのチップ化 / 単語分割の詳細規則（`isWordLike` の判定、前後空白の除去、空トークンの破棄） | Vitest（`src/core/tokenize.ts` の単体テスト） | 分割規則は純粋関数の入出力で網羅するのが適切。E2E では代表ケース（TP-010・TP-011・TP-012）のみ確認する |
| 4 象限ボードの表示 / チップ 1000 件時のスクロール・描画性能（仕様書 §12） | 実機手動検証（受け入れ基準） | 非機能要件であり合否の閾値が体感依存。仮想化しない方針の妥当性を実機で確認する |
