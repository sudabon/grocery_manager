# Test Plan

specs/dictionary-management/spec.md（10 シナリオ）、specs/app-settings/spec.md（10 シナリオ）、
specs/data-portability/spec.md（9 シナリオ）の全 29 シナリオを、E2E で検証可能な観点へ翻訳したもの。
受け入れ基準の原本は spec のシナリオであり、本ファイルで新しい仕様は定義しない。

前提:

- 確認ダイアログはアプリ内の `<dialog>` であり、ブラウザのネイティブダイアログは使わない（design.md - D6）。したがって E2E からロール・名前で操作できる
- エクスポートは共有機能を無効化した fixture でダウンロード経路に固定して検証し、共有経路はスタブで呼び出しを観測する（design.md - D9）
- インポートは `tests/e2e/fixtures/files/` の固定ファイルをファイル選択へ渡す
- 実行プロジェクトは `chromium` と `mobile-safari` の 2 面

### 異常系・境界の検討結果

- **異常系**: 壊れた JSON（TP-022）、版数不一致（TP-025）を E2E に含めた。フィールド欠損・型不一致・象限値域外の網羅は Vitest へ委譲（下表）
- **権限境界**: 認証・権限の概念がないため該当なし。ただし破壊的操作（メモ全削除・上書きインポート）の確認経路は TP-017 / TP-018 / TP-027 で必ず検証する
- **多重送信**: 辞書保存ボタンの連打を TP-030 で確認する。インポートの二重適用は確認ダイアログ経由のため単一実行に閉じる
- **空データ**: 4 象限すべて空の辞書を TP-009 / TP-010 で確認する。メモ 0 件の状態でのエクスポートは Vitest（形式検証）へ委譲

## E2E対象外(委譲先と理由)

| シナリオ | 委譲先 | 理由 |
|---------|--------|------|
| 設定値の変更 / 待機時間は範囲外の値にできない（インポート経路でのクランプ） | Vitest（`src/core/portability.ts` の検証・クランプ） | インポートファイル経由で範囲外の値を与える経路は、値の組合せが多く純粋関数のテストが適切。UI 経路は TP-013 で確認する |
| 辞書/全データのインポート検証の網羅（必須フィールド欠損、型不一致、象限の値域外、設定値の型不正、メモの必須項目欠損） | Vitest（`src/core/portability.ts`） | 不正入力のバリエーションが多く、E2E で回すと実行時間に見合わない。E2E は代表 2 ケース（TP-022・TP-025）で「無変更であること」を確認する |
| エクスポートの受け渡し手段 / 共有シートから他アプリへ実際に保存できること | 実機手動確認（受け入れ基準） | iOS の共有シートはブラウザ外の UI であり自動化できない。`navigator.share` の呼び出しまでを TP-029 で確認する |
| アプリ情報とプライバシー方針の提示 / ストレージ永続化の要求結果の値（許可/不許可） | 実機手動確認 ＋ Vitest（`navigator.storage.persist` のモック） | 許可結果はブラウザとインストール状態に依存し、E2E で意味のある値を作れない。表示欄の存在は TP-019 で確認する |
| 保存時の整形 / 数千語規模の単語リスト保存時の応答性 | 実機手動確認 | 非機能要件であり合否が体感依存。明示保存であるため待たせても実害が小さいという設計判断（design.md - Risks）の妥当性を確認する |
