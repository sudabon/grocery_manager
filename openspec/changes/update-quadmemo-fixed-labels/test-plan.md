### 異常系・境界の検討結果

- **異常系**: 不正な JSON のインポート（TP-009）を含めた。ラベルを含む JSON のインポート（TP-008）も、旧形式との互換という意味で境界に当たる
- **権限境界**: ラベルは利用者操作で変更できなくなるため、権限の概念は該当なし。「変更手段が存在しない」ことは TP-003 で確認する
- **多重送信**: 辞書保存の連打は `add-quadmemo-dictionaries` の既存観点で担保済み。ラベル固定化で保存の引数が変わるだけなので独立観点にはしない
- **空データ**: 単語リストが空の辞書でもラベルが表示されることは TP-001（`seed:dict-basic` は Q4 の entries が空）で併せて確認する

## E2E対象外(委譲先と理由)

| シナリオ | 委譲先 | 理由 |
|---------|--------|------|
| 共有画像内の象限ラベルが固定値であること | Vitest（描画入力の純粋関数） | PNG のピクセルから日本語を読むのは E2E に向かない。`add-quadmemo-board-image-share` design - D5 と同じ判断。`boardImageLayout` が返すラベルが固定値であることをユニットで検証する |
| 固定ラベルが共有画像の描画幅（431px）に収まり圧縮されないこと | Vitest（`fillText` の maxWidth 記録） | 最長 `ドラッグストア` 7 文字（`肉類・乳製品` は 6 文字）で構造的に収まる。実際の字形の見え方は環境依存で自動判定できない（design.md - D5） |
| `Dictionary.label` フィールドが IndexedDB に残っていること | Vitest（repository の単体テスト） | 保存層の内部構造であり外部から観測できない。design.md - D2 の判断を単体で固定する |
| 辞書エクスポート JSON の往復（ラベルなし → インポート） | Vitest（`portability.ts` の単体テスト） | 新旧形式の受理・非文字列ラベルの拒否・往復の構造検証は単体で十分。E2E は受け渡し手段（TP-007）までを見る |

## タグ対応

- すべての実装テストに `@update-quadmemo-fixed-labels` と `@TP-NNN` を付与すること
- 既存 fixture `seed:dict-basic` / `seed:dict-custom-labels` / `env:web-share-stub` / `files/dictionaries.json` / `files/broken.json` は登録済みのものを再利用する
- `seed:dict-custom-labels` はラベルの差し替えが本 change で表示に影響しなくなるため、`tests/e2e/fixtures/README.md` の説明を「ラベルは表示に使われない」旨へ更新すること
- 本 change で意味を失う既存観点（`add-quadmemo-dictionaries` の「象限ラベルを変更するとメモ画面に反映される」）は、実装時に削除または TP-003 の形へ置き換えること
