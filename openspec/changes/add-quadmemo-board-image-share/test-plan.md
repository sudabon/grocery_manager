# Test Plan

specs/board-image-share/spec.md の全 9 シナリオを、E2E で検証可能な観点へ翻訳したもの。
受け入れ基準の原本は spec のシナリオであり、本ファイルで新しい仕様は定義しない。

前提:

- 共有シートそのものはブラウザ外の OS UI であり自動化できない。呼び出しは `env:web-share-stub` で観測し、ダウンロード経路は `env:no-web-share` で固定する（design.md - D5。JSON エクスポートと同じ方式）
- 画像にラベルとチップ本文が正しい象限で含まれることは、描画入力の純粋関数を Vitest で検証する。E2E は PNG として渡されたこと（`type` とファイル名）までを見る
- オフライン観点はビルド成果物を配信する `pwa` プロジェクトで実行する（design.md - D6）。その他の観点は開発サーバーの `chromium` と `mobile-safari`

### 異常系・境界の検討結果

- **異常系**: 受け渡し失敗（TP-007）とキャンセル（TP-005）を含めた。画像組み立て失敗（Canvas 非対応）は対象プラットフォーム外として下表へ委譲する
- **外部送信**: spec の「アプリから外部へ自動送信してはならない」を TP-009 で確認する。`externalRequests` fixture で配信元以外へのリクエストが空であることを見る方式は `add-quadmemo-classification` と `add-quadmemo-pwa-offline` の既存観点と同じ
- **権限境界**: 認証・共有先の指定はアプリ側に無い（OS の共有シートが担う）ため該当なし
- **多重送信**: 画像共有を連続実行してもメモが増えないことは TP-006 の「データ無変更」で担保する。独立観点にはしない
- **空データ**: メモ 0 件を TP-001 / TP-002 で確認する

## E2E対象外(委譲先と理由)

| シナリオ | 委譲先 | 理由 |
|---------|--------|------|
| ボード画像の内容 / チップがあるボードの画像にラベルと本文が含まれる（象限配置・全チップ・操作 UI を含めないこと） | Vitest（描画入力の純粋関数） | PNG ピクセルから日本語と配置を読むのは E2E に向かない（design.md - D5）。E2E は PNG として渡されたことを TP-003 で確認する |
| 画像の受け渡し手段 / 共有シートから LINE 等の他アプリへ実際に送れること | 実機手動確認 | iOS の共有シートはブラウザ外の UI であり自動化できない。`navigator.share` の呼び出しまでを TP-003 で確認する |
| ボード画像の内容 / キャンバス上の日本語の欠け・色の見え方 | 実機手動確認 | フォントレンダリングは環境依存で自動判定できない |
| 画像共有の失敗案内 / Canvas 自体が使えない環境 | 対象外（手動確認は任意） | 対象プラットフォーム（iOS Safari）は Canvas に対応している。失敗時の案内経路は TP-007 で代表する |

## タグ対応

- すべての実装テストに `@add-quadmemo-board-image-share` と `@TP-NNN` を付与すること
- TP-008 は `pwa` プロジェクトで実行すること
- 新規 fixture `env:web-share-abort` / `env:web-share-failure` を `tests/e2e/fixtures/README.md` に登録すること
- 既存 fixture `seed:empty-board` / `seed:memos-across-quadrants` / `env:no-web-share` / `env:web-share-stub` / `env:built-app-offline` は登録済みのものを再利用する
- 共有スタブはファイルの `name` と `type` を記録するよう更新し、既存の JSON エクスポート E2E が回帰しないこと
