# Test Plan

specs/static-hosting/spec.md の各シナリオを、E2E で検証可能な観点へ翻訳したもの。
受け入れ基準の原本は spec のシナリオであり、本ファイルで新しい仕様は定義しない。

前提: 本 change の E2E は **配信済みの CloudFront 配信ドメイン** に対して実行する。
`E2E_BASE_URL` が配信サブドメインを指している場合のみ意味を持つ観点であるため、
ローカル開発サーバーに対しては実行対象外とする。

### 異常系・境界の検討結果

- **異常系（存在しない拡張子付きファイル）**: `/does-not-exist.png` のような実体なしパスも 403/404 → `/index.html` 200 に写るため、SPA フォールバックとしては TP-003 と同一の経路。追加観点は設けない
- **権限境界**: オリジン直アクセス拒否は配信ドメインの外側の URL を叩く検証であるため E2E 対象外（下表）
- **多重送信**: 静的配信に副作用のある操作が無いため該当なし
- **空データ**: 配信物が空になるケースはデプロイ操作の不備であり、TP-001 が失敗として検出する

## E2E対象外(委譲先と理由)

TP-005 のヘッダー検証だけではエッジ側の TTL は証明できない。カスタムポリシーの最低・既定 TTL が 0 秒、最大 TTL が 31536000 秒であること、403/404 のエラー TTL が 0 秒であることを Terraform のコードと適用結果で確認する。S3 フォールバックのみ最小 1 秒を許容し、通常のエントリポイントにはこの例外を適用しない。

| シナリオ | 委譲先 | 理由 |
|---------|--------|------|
| HTTPS でのアプリ配信 / TLS 1.2 以上のみを受け付ける | Terraform コードレビュー（`infra/cloudfront.tf` の `minimum_protocol_version`） | TLS ネゴシエーションの検証であり、Playwright の HTTP レイヤからは受理する TLS バージョンを指定できない |
| オリジンの非公開 / オリジンへの直接アクセスが拒否される | 手動確認（`curl` で S3 オブジェクト URL を叩く）＋ Terraform コードレビュー | 配信ドメイン外の URL に対する検証であり、アプリの E2E ではなくインフラ検証。バケットポリシーとパブリックアクセスブロックの設定で担保する |
| 更新が届くキャッシュ制御 / ハッシュ付きアセットは長期キャッシュされる | デプロイ手順内の確認（`aws s3api head-object`） | 本 change の配信物はプレースホルダーでハッシュ付きアセットが存在しない。実アセットが出るのは Vite ビルド導入後で、その時点で `add-quadmemo-pwa-offline` の観点として検証する |
| デプロイによる更新反映 / デプロイ後にリロードで新バージョンが反映される | 手動デプロイ検証（M0 完了条件） | デプロイ実行そのものを E2E から起動しない方針（AWS への副作用と無効化の待ち時間が入るため）。デプロイ後に TP-001 を再実行することで内容の反映を確認する |
| デプロイによる更新反映 / 削除されたファイルが配信から消える | 手動デプロイ検証（`aws s3 ls`） | 同上。`--delete` 付き同期の効果確認はインフラ運用側の検証 |
| 配信インフラの再現可能な構成管理 / 再適用で差分が出ない | `terraform plan` の実行結果確認 | Terraform の冪等性検証であり E2E の対象外 |
| 配信インフラの再現可能な構成管理 / 手動登録すべき DNS レコードが提示される | `terraform output` の実行結果確認 | 構成ツールの出力確認であり E2E の対象外 |
